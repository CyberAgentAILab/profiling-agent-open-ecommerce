Your task is to profile a buyer based on the product(s) in their purchase history shown below, producing THREE attribute groups in a SINGLE JSON response:
  1) demographic     — "who the buyer is"             (fixed personal/household traits)
  2) psycho_behavioral — "how the buyer thinks/acts"  (ongoing lifestyle, hobby, dietary practice, fandom, value affiliation, pet ownership, media consumption)
  3) life_event      — "what changed recently"        (life-stage transitions: marriage, childbirth, relocation, retirement, school enrollment, empty nest, job change, bereavement, plus adjacent transitions like pet acquisition, divorce, caregiving onset, hospitalization, deployment, immigration)

For EACH group, produce two layers of output:
- (Layer 1) selection_answers: closed-choice answers for a fixed set of categories. Every category MUST be answered for every input. Use "unknown" when the input is not diagnostic for that category.
- (Layer 2) free_description_attributes: a free-form list of 0-3 ADDITIONAL atomic attributes that the Layer 1 categories CANNOT express. Return an empty list when Layer 1 already captures everything. This list feeds a downstream clustering step.

- Input format you will receive (a single JSON object):
  - items: an array of one or more purchased items (from frequent-pattern mining over the buyer's history; may be a single item or multiple co-occurring items). Each item has:
    - product_name: original platform title (retains brand, model, size, packaging)
    - canonical_name: brand-free product description

- Conditions:
  - The user purchased the item(s) on Amazon. You are profiling from these purchase(s) only; aggregate inference happens downstream.
  - **SCOPE SEPARATION**: each group MUST contain ONLY attributes that belong to it. Demographic = fixed personal/household traits; psycho_behavioral = ongoing lifestyle/hobby/diet/fandom/affiliation/pet/media; life_event = a life-stage transition. The defining feature of a life-event attribute is **recency of change** — a stable, ongoing trait is NOT a life_event.
  - "Recent" (life_event only) means the transition happened (or is imminent) within roughly the last 12 months.

- Rules for applying to all three groups
  - Layer 1:
      - Each selection_answer entry is {"category": "<category label>", "reason": "<one-sentence justification>", "attribute": <value>}, emitted for every category in the group's enum, in the listed order.
      - Use "unknown" (or the string "unknown" for array-valued categories) whenever a generic purchase carries no specific evidence. Most generic products yield mostly "unknown".
      - The reason field must cite a concrete property of the product (intended user, price tier, cultural specificity, channel, intended use, brand-tier, repeat-purchase implication), not vague speculation.
      - DO NOT invent categories not listed in each group's enum.
      - **STRICT ENUM**: for each category, `attribute` MUST come from THAT category's closed list — never borrow a value from another category's enum even if semantically related. When in doubt, return "unknown" rather than borrowing.
  - Layer 2:
      - 0 to 3 items. **Return `[]` (and `{}` for confidence) when Layer 1 already captures everything you can confidently infer** (e.g. a generic USB-C cable — see Example 1).
      - **Scope**: use Layer 2 ONLY for finer-grained dimensions of the SAME group that the Layer 1 enums cannot express. Each group section below lists which dimensions qualify.
      - **DO NOT restate Layer 1**: an attribute that essentially repeats a Layer 1 category of the SAME group belongs in Layer 1 and MUST be excluded from Layer 2 (e.g. demographic "adult aged 55 or older"; psycho_behavioral "user has an athletic and active lifestyle").
      - **DO NOT include out-of-scope attributes** — route them to the correct group per SCOPE SEPARATION above: hobby/fandom/collecting → psycho_behavioral; fixed personal/household trait → demographic; recent transition → life_event. In particular, an ongoing trait disguised as a transition ("took up / initiated / expanded a hobby") is a stable interest and belongs in psycho_behavioral, NOT life_event.
      - Each item is ONE atomic attribute with a SINGLE unambiguous meaning. The downstream pipeline embeds and clusters each string, so compound attributes break clustering. DO NOT bundle: split "first-generation immigrant nurse in a multi-generational household" into "first-generation immigrant in the United States", "works in the nursing profession", "lives in a multi-generational household".
      - Each string is a noun phrase or short clause in English, 5 to 20 words, with NO brand names and NO specific city/state/postal code.
      - If the only inferences for a group are out-of-scope, return an empty Layer 2 list rather than smuggling them in.
      - **Format — prefix convention by group**:
          - demographic: a bare noun phrase (do NOT prefix with `user` or `household`).
          - psycho_behavioral: begins with `user ` and is a single subject-verb clause.
          - life_event: begins with `user or household ` and MUST describe a recent transition or change, not a stable trait.
  - confidence:
      - For each attribute, confidence is the expected fraction (0.0-1.0) of buyers whose history includes these item(s) who would match it: out of 100 such buyers, how many match?
      - Rare → small (5/100 = 0.05). Common → large (80/100 = 0.80). Each attribute is scored INDEPENDENTLY; values need NOT sum to 1.0.

==============================
GROUP 1 — user_attribute_demographic
==============================

- Layer 1 — selection_answers (ALWAYS emit all 7 entries, in this order):

  Categories and allowed values:
    - signal:age-bin
        attribute = array of 1-2 ADJACENT bins from ["18-24","25-34","35-44","45-54","55-64","65+"], or the string "unknown"
    - signal:gender
        attribute = "male" | "female" | "other" | "unknown"
    - signal:income-bin
        attribute = array of 1-3 ADJACENT bins from ["<25k","25-49k","50-74k","75-99k","100-149k","150k+"], or the string "unknown"
    - signal:education
        attribute = "<high-school" | "high-school" | "bachelor" | "graduate" | "unknown"
    - signal:occupation-class
        attribute = "blue-collar" | "white-collar" | "professional" | "service" | "student" | "retired" | "unemployed" | "unknown"
    - signal:ethnicity
        attribute = "asian" | "black" | "hispanic" | "white" | "other" | "unknown"
    - signal:location-type
        attribute = "urban" | "suburban" | "rural" | "unknown"

- Layer 2 qualifying dimensions (demographic) — see common Layer 2 rules above for scope, format, and exclusions:
    - specific occupation, household-composition slice (single parent, multi-generational, single adult living alone), language community, religion, marital status, military/veteran affiliation, immigrant status, family-size group, disability status.

==============================
GROUP 2 — user_attribute_psycho_behavioral
==============================

- Layer 1 — selection_answers (ALWAYS emit all 4 entries, in this order):

  Categories and allowed values:
    - signal:lifestyle
        attribute = array of 1-3 values from
          ["bohemian-creative","athletic-active","outdoor-adventurer","urban-trendy",
           "traditional-conservative","tech-enthusiast","family-oriented","home-improver",
           "budget-conscious","luxury-oriented","eco-sustainable","gourmet-foodie"],
        or the string "unknown"
    - signal:personality
        attribute = array of 1-2 values from
          ["practical-pragmatic","fashion-individualist","social-extrovert",
           "reserved-introvert","adventurous-risk-taker","status-conscious",
           "nurturing-caregiver","analytical-detail-oriented"],
        or the string "unknown"
    - signal:purchase-occasion
        attribute = "routine-everyday" | "seasonal" | "special-occasion" | "gift-giving" | "emergency" | "unknown"
    - signal:benefit-sought
        attribute = array of 1-3 values from
          ["price-economy","quality-premium","convenience","durability",
           "health-wellness","status-prestige","customization","sustainability",
           "safety","performance","aesthetic-design"],
        or the string "unknown"

- Layer 1 answering rules (psycho_behavioral-specific):
  - The `signal:lifestyle` enum contains EXACTLY these 12 values and nothing else: `bohemian-creative, athletic-active, outdoor-adventurer, urban-trendy, traditional-conservative, tech-enthusiast, family-oriented, home-improver, budget-conscious, luxury-oriented, eco-sustainable, gourmet-foodie`. If a value you are about to emit is not literally in this list, replace it with `"unknown"` or pick the closest member of this list.

- Layer 2 qualifying dimensions (psycho_behavioral) — see common Layer 2 rules above for scope, format, and exclusions:
    - specific hobby (rock climbing), specific diet (vegan, keto, gluten-free), specific household habit, specific fandom, political/value affiliation, pet ownership, media-consumption pattern, religious practice, recovery-from-addiction status.

==============================
GROUP 3 — user_attribute_life_event
==============================

- Layer 1 — selection_answers (ALWAYS emit all 8 entries, in this order):

  Categories and allowed values (each attribute = "positive" | "negative" | "unknown"):
    - signal:recent-marriage              (positive = recently got married or engaged)
    - signal:recent-childbirth            (positive = recently expecting or had a child)
    - signal:recent-relocation            (positive = recently moved residence)
    - signal:recent-retirement            (positive = recently retired or transitioning to retirement)
    - signal:recent-school-enrollment     (positive = a household member recently started a new school stage, e.g., college, K-12 enrollment)
    - signal:recent-empty-nest            (positive = a child recently left the household)
    - signal:recent-job-change            (positive = recently changed job or started a new role)
    - signal:recent-bereavement           (positive = recently lost a spouse or close family member; covers solitary-survivor stage)

- Layer 1 answering rules (life_event-specific):
    - "positive" = the product is a STRONG, SPECIFIC signal that the transition recently occurred or is imminent — a product bought almost exclusively because of the transition (newborn diapers → recent-childbirth; moving boxes → recent-relocation; engraved wedding ring box → recent-marriage).
    - "negative" = the product specifically indicates the transition has NOT occurred (rare; prefer "unknown").
    - "unknown" = no specific evidence; the correct answer for most generic products.
    - **DEFAULT TO "unknown" UNDER UNCERTAINTY.** Do NOT emit "positive" on weak associative reasoning ("could be a wedding gift"). The signal must be SPECIFIC to the transition, not merely COMPATIBLE with it — most apparel, jewelry, decor, and gift-style items are routinely bought outside any transition. (e.g. a vintage-clasp belt or a generic candle set → recent-marriage "positive" is WRONG; an engraved wedding ring presentation box → "positive" is RIGHT.)

- Layer 2 qualifying dimensions (life_event) — see common Layer 2 rules above for scope, format, and exclusions:
    - pet acquisition/loss, divorce/separation, caregiving onset for an elderly parent, recovery from illness/injury, hospitalization, military deployment/homecoming, gap year/sabbatical, immigration/visa transition, financial-status transition, home renovation.

==============================
OUTPUT FORMAT
==============================

JSON only (no extra text, no markdown). Top-level object with EXACTLY these three keys:
  - "user_attribute_demographic":     {"consumer_attributes": [ <7 selection_answers in the demographic order> , <free_description_attributes entry> ]}
  - "user_attribute_psycho_behavioral": {"consumer_attributes": [ <4 selection_answers in the psycho_behavioral order>, <free_description_attributes entry> ]}
  - "user_attribute_life_event":      {"consumer_attributes": [ <8 selection_answers in the life_event order> , <free_description_attributes entry> ]}

For every group:
  - The selection_answer entries appear FIRST, in the exact order listed in that group's Layer 1 enum.
  - The free_description_attributes entry appears LAST.
  - All entries have "category", "reason", "attribute" keys. The free_description_attributes entry additionally has "confidence".
  - Use double quotes; no trailing commas; null is JSON null (not the string "null").
